# 架构与职责边界

Harness Devflow 将流程质量、宿主执行能力和 Agent 执行引导分开。专业 Skills 与 Python 核心随目录分发，消费项目提供自己的检查命令与交付工具。

## 分层

| 层 | 实现 | 职责 |
| --- | --- | --- |
| 流程核心 | `engine.py`、`model.py`、`storage.py` | 阶段依赖、验收覆盖、配置、批准、真实证据、原子状态和恢复 |
| 执行引导 | `guidance.py`、各 Skills | 生成下一任务和上下文，逐任务检查点或自主批量提交，专业方法路由 |
| 宿主适配 | `hosts.py`、`executors.py` | 显式能力选择、命令桥接、原生工作树身份校验、统一结果 |
| 内置执行 | `executors.py`、`worktrees.py`、`git.py` | 命令执行、超时与日志、串行依赖任务、工作树创建和恢复合并 |
| 项目交付 | `runner.py`、`gates.py`、`adapters/` | 接入真实检查和交付操作，将结果关联到当前代码和流程 |
| 专业产物 | `capabilities.py`、`knowledge.py` | 随包专业方法、请求与资源快照、基线交接和可选知识保存 |

`runner.py` 管理一次执行的状态事务，具体命令执行由 `executors.py` 提供。宿主桥接和内置子进程返回同一结果契约，检查命令成功后仍由核心校验代码是否变化、配置是否匹配及证据是否完整。

宿主品牌不代表工具可用性。默认 generic 使用内置命令和工作树，串行执行；实际可调用能力由项目配置声明。原生执行一旦开始就不会因失败、拒绝或结果不明而自动切换执行器。

## 引导与质量

`guided` 默认每次暴露一个实现任务及其验收和检查方式，核心强制按计划顺序记录检查点。`autonomous` 支持连续实现和有序批量提交。两者均校验最终任务覆盖、当前模块检查、审查发现和交付门禁。

检查点使用真实模块检查和不可覆盖的结果引用。历史增量的检查不要求永远匹配后续代码；最终模块检查重新验证组合结果。模型仍负责判断设计、测试与验收语义，程序不将格式正确等同于代码正确。

`next` 生成工作包并启动待执行阶段；`submit` 根据实际结果生成报告外壳，并关联当前成功的命令记录。专业 Skill 输入直接引用上游文档，避免重新生成相同内容。批量提交逐项持久化，遇到失败保留已完成前缀，遇到批准点停止。

## 工作区与状态

支持有初始提交的 Git 仓库、detached HEAD 和已有未提交修改。任务记录初始代码指纹及 dirty 状态；本地 checkout 模块可以验证未提交代码。worktree 模块必须在干净起点执行，并提交经过验证的修改后合并。

宿主 worktree 可以在消费仓库目录之外；接入时检查实际 Git common directory、准确起始 SHA、洁净状态及模块独占。后续检查持续验证目录身份。所有报告和日志仍保存在拥有任务的 checkout 内，工作树由创建方负责清理。

为已验证的 detached 工作命名分支后，`bind-branch` 在代码指纹保持一致的前提下记录新名称。该操作不改代码或凭空生成验证。其他分支/仓库身份变化会阻止错误复用任务。

状态只记录项目事实、产物、检查和交付进展，不复制宿主聊天记录。`handoff` 输出可供另一个宿主读取的同一 checkout 任务包；接手时 `next` 重新验证事实。跨机器文件传输和工作目录迁移需要独立安排。

## 失败与恢复

状态在一个 JSON 事务中保存，配合 OS 锁与原子替换。运行命令时释放状态锁，保留开始、进程和结束记录。并发操作有上限；缺少原生委派或选择引导模式时，模块按依赖串行推进。

检查失败消耗有界重试预算。原生执行结果不明或外部操作超时标记 unresolved；它阻止继续执行、改配置和重开，直到核实进程与外部状态并 reconcile。核实只能记录已处理失败，不能把不确定结果改成验证成功。具体项目适配器通过稳定幂等键与实际外部状态避免重复动作。

文档变化校验内容哈希；代码绑定结果比较 HEAD 与工作区内容指纹。重开阶段和重配保留历史，保守失效受影响后缀。流程核心不会根据模型自述推断精细依赖来复用不确定的旧证据。

## 权限与约束

所有模式沿用宿主权限与用户授权。原生能力声明不是授权，批准注记不是身份认证。模板中存在部署适配器不代表允许部署。内置流程可以在无原生调度环境中按需运行和恢复；后台唤醒需要实际可用且获授权的调度系统。

本地校验与可选 Git Hook 降低流程错误；组织级强制要求由 CI 和托管平台实现。发行目录不含状态迁移器、旧命令别名或双轨运行时。完整契约见[运行时文档](../skills/flow/references/runtime.md)和[宿主契约](../references/hosts.md)。

## 精确接手与证据复用

`start-review` 使用独立的 review 入口，保留明确基线和验收，跳过未执行的开发阶段。`pushed` 终点只选择推送及显式配置的其他检查，Git adapter 在推送后核验远端 SHA。

`reuse.py` 只复用显式声明为确定性的本地 review 检查。内容与环境指纹独立于 Git 提交，原始执行时间和日志保留，提交/交付时再次校验；最终 review 及交付仍受 HEAD 绑定。`context.py` 根据阶段依赖筛选资料并记录已读内容 ID，不影响验证门禁。

`groups.py` 关联多个独立 Git 任务，固定提交、校验依赖声明和真实联调记录。各仓库继续独立执行，group 不替代发布授权，也不把本地验证解释为线上生效。
