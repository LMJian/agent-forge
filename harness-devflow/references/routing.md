# One workflow owner per task

1. Honor the user's explicit plugin selection and applicable project instructions.
2. For an existing task, resume its recorded owner. Do not create a Harness task to mirror an
   active ai-devflow task, or the reverse. Migration requires an explicit scope decision and
   current evidence; never translate old stages into invented successful reports.
3. When Harness is the configured default and no owner exists, use Harness for generic
   development, existing-change review and delivery. Questions/research do not start workflows.
4. A provider-specific tool or professional skill may assist the current owner without taking
   over its state machine. Select only the needed capability, not a second complete workflow.
5. Multiple installed copies do not imply multiple executions. Compare marketplace, version and
   actual configured paths. Keep only one default workflow plugin enabled when automatic
   routing is ambiguous; preserve other installations and configuration backups for rollback.

For Codex, plugin enable/disable is host configuration, not a rule to duplicate in every Skill
or the user's global AGENTS.md. Re-enable an alternate plugin when explicitly selected or
needed for a task it owns. Never uninstall alternate plugins or delete task data merely to tidy
the skill catalog. Installation updates must be verified against the actual installed cache,
and a new thread is the reliable boundary for loading updated discovery instructions.
