# 飞书事项上下文收集

从用户提供的种子逐跳查询文档、表格、群、消息、会议与相关人员，形成带出处的交接背景包。查询使用用户本人权限；不预建或持久化全域关系库。结果是标明收集时间与覆盖边界的快照，不承诺穷尽全部历史。

## 正文写作规范

本规范适用于本地背景包、飞书文档、HTML 正文和会话摘要。

以有经验的后端开发工程师和善于教学的技术作者的视角写作。默认读者有约 2 年业务后端开发经验，但不了解相关业务。围绕读者理解和接手工作所需的信息安排详略，保证可读性。

- 先讲清楚事项是什么、为什么重要、解决什么问题，再从直觉理解逐步讲到技术原理。
- 关键术语首次出现时作必要解释，结合实际应用场景说明机制与取舍。
- 需要代码示例时，给出能说明问题的最小示例。标明示意代码，避免与已核验的实现混淆。
- 图片有助于理解时，提供图片或示意图，说明关键关系、流程或操作。

全文必须遵守 ASD-STE100 受控语言规范。由于正文使用中文，应严格采用其核心原则：一词一义、句子简短、主动语态优先、一次只表达一个动作或判断、明确动作主体、避免歧义代词和隐含逻辑、统一术语。同一对象不得换用近义词。交付前逐段检查并修正不符合项。

## 交付与范围

默认交付本地 `background.md` 和会话摘要，附关键出处与关系清单；不默认生成网页或创建远端内容。按用户明确的载体选择后续动作，不为例行选择重复询问：

| 用户要求 | 交付动作 |
|---|---|
| 整理背景/交接包，未指定载体 | 本地背景包；不调用远端写接口 |
| 飞书文档/写入飞书 | 背景包 + 一篇新的飞书文档及关系图 |
| 网页/HTML | 背景包 + 本地 `index.html`；不隐含创建飞书文档或发布 |
| 发布妙搭页面/上线网页版 | 背景包 + HTML + 新应用发布；是否同时写飞书取决于用户要求 |
| 只读/仅本地 | 禁止远端写入；用户要求的本地 HTML 仍可生成 |

- 沿用用户已明确的交付与发布授权，不重复询问。若要求网页但未授权发布，先完成本地页面；确需询问发布时以可审阅的产物为依据。不向只要求背景包的用户例行追加发布问题。
- “只要文档”不生成 HTML；“不要发布”禁用妙搭发布，但用户明确要求的飞书文档仍可创建。含“只读/不写外部内容”的约束优先；矛盾要求需消歧，不自行扩大权限。
- 收集阶段仅做只读查询。不得发消息、拉群、申请权限、改已有文档或扩大共享范围。输出到已有文档需要用户指定目标，不能当作默认的新建操作。
- OAuth、安装/升级 CLI、Computer Use 和权限变更遵守当前会话的授权规则；不要把错误提示当作自动执行这些动作的授权。

## 启动

1. 从请求提取事项、种子、时间范围、待回答问题与交付载体。缺少种子不阻塞，可用事项名开始。同名项目先用已给的文档、团队、负责人或时间消歧；仍不能确定就列出候选询问，不合并不同项目的证据。
2. 读取 `lark-cli skills read lark-shared`。使用对应领域前按需读取其 Skill 与目标命令的 `--help`，以本机版本为准，不整批加载所有领域说明。
3. 默认使用 [轻量记录入口](references/quickstart.md)：一次初始化问题与时钟；每次联网请求预留并封存，来源/事实/覆盖按轮批量更新。完整背景包采用 `full` 覆盖，用户限定的局部问题可选 `targeted`。复杂技术调查、恢复或需要完整审计时再读 [事实与断点记录](references/state.md)，不用为普通任务加载全部 schema。
4. 首次探测跟随种子：文档先读目录，群名查群，消息或会议线索查对应域。不要求先找到文档。使用原生 CLI 和实际执行环境，封存响应、退出码和时间；`ok=true`、`identity=user` 才继续。新接口域先单次只读探测，不能用文档权限代替消息/会议权限；环境、身份或 profile 变化后重新探测。认证/网络失败停止批量，不自动登录、切 bot 或安装。
5. 默认检索预算 **40 次 / 10 分钟有效工作时间**，交付预算 **15 次 / 5 分钟**；首次请求前可按任务规模记录计划，用户上限为硬限制。分析和记账同样计时，真实等待用 pause/resume；缓存只在本次任务复用，保留身份、版本、读取范围与时间，不写入持久记忆。

用户要求技术架构、实现或文档与代码核对时，追加读取 [技术调查模式](references/code-investigation.md)。先收集飞书背景，再定位仓库并在深入代码前记录分支、commit、脏文件和远端核对边界；普通背景整理无需扫描仓库。

## 阶段一：收集 → 背景包

按需读取 [检索与证据规则](references/collection.md) 中相关入口与章节，围绕问题跨域发现、引用扩散和前史检查。完整背景包需登记文档、群、消息、会议、前史和决策讨论的覆盖；可以有理由地跳过，无需每个别名机械四搜。新增事实、解决的问题或实质矛盾才算收益；连续两轮无收益且无具体线索时暂停分支，预算耗尽交付缺口。

先在本地整理完整正文，推荐标题为「事项名 · 上下文背景包（agent 自动收集）」，包含：

| 内容 | 验收点 |
|---|---|
| 实体清单 | 按文档/表格/群/关键消息/会议/人分组；每项有名称、真实链接或 ID、一句话相关性；重要项在前 |
| 现状综述 | 不超过 200 个中文字，回答是什么、进展到哪、什么尚未闭环 |
| 时间线 | 日期 + 关键决策/转折/里程碑 + 出处；明确时区，不猜日期 |
| 关键决策与讨论脉络 | 结论、决策人/时间、备选方案与主要争论、最终取舍原因、讨论出处；缺证据的字段标明未查到 |
| 未决问题 | 口径矛盾、未收口争论、待决事项；分别列来源和建议询问的人，不擅自替人拍板 |
| 关系图 | 核心实体与有证据的关系，最多 30 个节点；完整清单留在正文 |
| 检索路径 | 查询了什么、为何展开、查到什么、何处受阻、何时停止 |
| 交接待办 | 权限缺口、未覆盖来源、需人工移交的口头背景；能确定时标出负责人 |

正文标注收集快照时间、查询范围与已知缺口。综述、时间线、决策和未决问题的每个事实判断均附可定位出处；区分直接事实、来源间冲突和明确标注的推断。没有依据时留缺口，不能为了填满表格补写。

关键结论先进入 `evidence.json`，再写入正文。明确区分“提议 / 已决定 / 已实施 / 运行中 / 未确认”；评审通过不能自动升级为已实施或运行中。新决定明确替代旧决定时保留历史与替代关系，旧决定退出当前结论；仅更新时间更晚或另一人表达不同看法不足以认定替代。文档、HTML 和关系图共同使用这一批核验后的事实。

登记实际文件和哈希后运行 `python3 <本技能目录>/scripts/check_artifacts.py check <任务目录>`。查看记录、文件、问题与 `collection_coverage`、预算、图和交付状态；退出码 0 只证明记录/文件检查通过。Mermaid 单独保存 `.mmd`，只使用现成解析器；没有则标 `not_checked`。未要求远端交付时直接交付本地文件，保留事实和覆盖缺口。

创建文档前读取 `lark-cli skills read lark-doc` 及其 `references/lark-doc-create.md` 指向的格式规范。优先在本地准备 DocxXML；进入产物目录，以相对文件引用执行一次 `docs +create --content @background.xml --as user`。关系图采用本机支持的 Mermaid 画板语法，见检索参考；不要留下空白画板冒充完成。

用 [远端交付记录](references/delivery.md) 的 `operation start/result/verify` 绑定输入文件、原生调用回执和窄回读，核验关键内容、revision 与画板结果。正文、XML 或图变化后旧回执不能证明新版本已交付。结果不确定记 `unknown`，先对账，不再次创建；失败仍交付本地文件。

## 阶段二：背景包 → HTML / 妙搭

仅在用户要求网页版时读取 [页面生成与发布](references/publishing.md)。阶段二只接收本次核验后的背景包、事实记录、已创建文档的链接/token（如有）和用户授权范围，不重新开展事实收集。页面失败不影响已完成的背景包或文档。

若执行环境允许且已授权委派，可让两阶段分别由新的子 agent 执行，阶段二等待阶段一交接。未启用委派时由主 agent 顺序完成，同样通过明确产物传递信息；不要求为此安装工具或开启额外能力。

## 完成汇报

简要给出文档链接、已确认的发布态 URL（若发布）、实际可见范围、本地产物路径，以及影响使用的缺口。区分“本地生成”“文档已创建”“页面已发布”“可见范围已核验”。管理链接不能替代发布态链接；未核验的可见范围不能描述为已确认仅本人可见。

命中预算或有关键覆盖缺口时，说明实际调用尝试数、有效时间、停止原因和未回答问题；失败、翻页和重试均计数，不能声称是 HTTP 请求总数。collection 耗尽进入已预留的交付阶段，总预算耗尽立即停止扩展，只保存已有记录并汇报缺口；不能以“收尾”为由继续调研或隐去超时。Skill 维护验证按 [离线场景](references/evaluation.md) 执行，日常收集无需加载该文件。

调用示例：

- `用 $lark-context-explore 整理「项目名」的完整上下文，种子是这个文档链接，生成交接背景包。`
- `收集「项目名」的来龙去脉，生成飞书文档并发布妙搭页面，保持默认可见范围。`
- `用 $lark-context-explore 只读收集「项目名」最近三个月的背景，结果保存本地，不创建飞书内容。`
