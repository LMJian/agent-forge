# 技术调查模式：飞书背景 → 仓库核对

仅当用户要求架构、代码实现、调用链或设计与代码差异时加载。不启动开发、测试环境、部署或远端写入。优先只读 CLI/API；Computer Use 仍须本次明确授权。

## 顺序和版本边界

1. 先读飞书种子目录和关键章节，建立项目别名、业务问题、系统边界、组件、仓库/接口线索和设计日期。取舍问题再追评审、历史讨论。
2. 从明确仓库链接或本地窄范围 rg 定位仓库；深入代码前记录路径、分支、完整 HEAD、工作区改动、观察时间。不扫描所有仓库后再猜项目。
3. `run_state.py repository <任务目录> --id repo1 --file <仓库绝对路径>` 只做本地 Git 读取，不 fetch/checkout/clone。无法核对远端则标 local_snapshot，不把旧分支称为当前线上实现。
4. 需确认远端时，用已获准的只读 `git ls-remote <明确remote> refs/heads/<明确branch>` 保存回执；再以 `repository ... --remote-result <回执路径>` 登记新快照 ID。另记远端查询时间与实际 remote；不改工作树。跨分支、dirty、无法联网或 HEAD 不一致要说明边界。HEAD 一致也只是当时远端代码状态。
5. 从路由/consumer/RPC handler 沿实际调用追到服务、策略、存储、外部调用及返回/异步闭环。rg 定位后窄读函数、配置和契约；跨仓库先确认接口再追下游，避免泛扫生成代码/vendor。

代码来源追加到 evidence.sources，时间用本次实际读到文件的时间：

```json
{"id":"code1","kind":"code","locator":"/真实仓库/service.go:42 Handler","access":"readable","observed_at":"实际ISO时间","fetched_at":"实际ISO时间","recorded_at":"实际登记时间","provenance":"direct","repository_id":"repo1","commit":"完整HEAD","file":"service.go","line":42,"symbol":"Handler","sha256":"所读工作区文件SHA256"}
```

file 是仓库相对路径，哈希固定本次内容；dirty 时 commit 仅表示基线，正文说明包含未提交改动。校验检查文件、行号、哈希，读后变化会失效。implemented claim 标 implementation_scope=local_snapshot；仅干净工作区与对应远端分支回执一致才可标 current_code。

## 六类问题与验收

按用户实际问题先建矩阵再扩散，每行列结论、文档出处、代码路径/函数/配置、证据状态、缺口。不是每行都必须有全部证据类型。

| 问题 | 关键核对 |
|---|---|
| 问题与系统边界 | 发起者、输入输出、归属、外部依赖、明确不承担的职责 |
| 模块与上下游 | 职责、接口、数据/控制方向；区分项目代码与公共平台 |
| 完整请求链路 | 入口鉴权/分流、处理、持久化、异步/回调、成功/失败；区分同步返回与任务完成 |
| 具体实现位置 | 绝对文件路径和行号、函数/类型、配置键及读取点、调用双方 |
| 历史取舍 | 决策记录、备选项、约束、日期；代码不能反推决策原因 |
| 差异和待确认 | 设计版本与代码快照；区分明确不一致、未找到、旧分支、线上未验证 |

找不到关联问题的宽泛搜索停止。代码问题 requires 包含 code；设计/实现对照包含 document+code。只有用户确需线上核验才加入 runtime，不因缺运行权限无限查找。

- **设计方案**：proposed/decided，有正文或决策段落。文档写“已上线”仍是来源陈述，可列“文档声称”。
- **代码已实现**：implemented，有代码路径和版本边界；配置声明不等于线上生效。
- **线上已验证**：operating，有 direct runtime 来源，含环境、部署 revision、观测时间、日志/trace/监控/只读接口回执定位，并关联代码版本。没有则标“未验证”，不能用会议转述升级。

## 报告与图

Markdown 按问题组织，开头列范围、文档读取时间/revision、仓库分支/HEAD、线上证据边界。关键判断逐条附文档章节或绝对代码路径，保留覆盖表和差异/未确认清单。

架构图保存 architecture.mmd，展示入口、模块、存储、外部系统和有证据的箭头；实线表示已核对调用，虚线表示设计或待核对，附图例。复杂请求另画 sequenceDiagram，区分同步返回与异步完成。每条重要边在报告有出处，不能把设计模块画成已运行。语法检查按 state.md；没有解析器注明未校验，不用 GUI 代替。

研究任务不修改业务代码、拉取并覆盖分支、运行可能写外部系统的测试、创建飞书文档或发布页面；明确授权的交付另按主流程处理。
