# 背景包页面与妙搭发布

## 单一事实来源

仅在用户要求网页时进入本流程。使用本次已核验的 `background.md`、`evidence.json` 和关系记录，不新增事实。若用户同时要求飞书文档且文档已创建，复用与其已核验 revision 一致的本地正文；本地正文缺失或文档已被修改时再有针对性地读回，避免为制作网页默认重复拉取全文。未创建飞书文档不阻塞本地页面或已授权的妙搭发布。

只调整呈现，不新增事实、改写判断强度或补猜决策人。文档的来源锚、冲突、限制、快照时间均保留；检索路径的详细操作日志不搬上页面，但覆盖缺口不能省略。

“已替代”的历史决定不能出现在当前结论卡片；提议不能改为承诺，评审通过不能改为已上线。页面构建前检查记录一致性；正文、事实记录与已发布文档有差异时先对齐，不自行任选一个版本。

## 生成单文件

在独立干净目录中生成 `index.html`，不与查询响应、凭据、临时文件混放。

- CSS/必要 JS 全部内联，无外部 CDN、字体、脚本、图片、分析埋点或网络请求。原文链接作为可点击导航保留。
- 中文响应式排版，字体栈使用 `PingFang SC, Microsoft YaHei, sans-serif`。优先清晰阅读、键盘可访问和窄屏可用，避免仅靠颜色表示状态。
- 推荐顺序：现状综述 → 决策卡片 → 时间线 → 分组实体清单 → 未决问题 → 交接待办 → 关系图。页脚显示收集快照与“agent 自动收集”。
- 关系图用内联 SVG；复杂图降级为可读的分组关系清单，不依赖外部 Mermaid CDN。保持与文档相同的证据关系。
- 来自文档、消息、标题和 URL 的内容按 HTML/属性上下文正确转义；只允许合适的 HTTP(S) 原文链接，不能把原始内容拼成可执行代码或 `javascript:` 链接。
- 本地检查 HTML 结构、链接、无意外外部依赖和内容覆盖。没有 Computer Use 授权就不用浏览器自动化或 UI 截图验证，不能声称已做视觉验收。

## 发布前

先完成可审阅文件，再判断会话是否已授权发布。明确要求“发布妙搭页面/上线/可访问链接”的授权可直接沿用；只要本地或未授权发布则交付文件，必要时一次性询问是否发布。不得把普通整理请求自动扩张为公开分享。

实际发布时读取 `lark-cli skills read lark-apps` 及 `references/lark-apps-html-publish.md`。缺少认证/scope 时说明缺口，遵守会话的 OAuth 授权限制；不要为本地生成步骤预先启动登录或安装。可授权后的登录范围以当前命令返回的必要 scope 为准。

先量尺寸：单个 HTML ≤ 10 MB、压缩包 ≤ 20 MB、未压缩候选文件总量 ≤ 200 MB；以本机 CLI 给出的限制与单位为最终准据。任一超限立即停止发布，报实测数值和本地路径；不能自行拆包、绕过限制或加 `--allow-sensitive`。

## 创建与发布

新的一次收集新建一个 HTML 应用，不复用已有 app 覆盖用户内容。同一次任务的恢复/重试复用已记录的 app_id；用户明确要求更新某个既有应用时，先定位并按其授权范围处理。

按 [远端交付记录](delivery.md) 使用 operation 命令绑定 HTML 输入和原生调用回执。已有成功 app_id 就复用；inflight/unknown/submitted 先按 [断点对账](state.md) 查询。新应用实际权限须由 access-scope-get 原始回执核验，通过 app verify 后才能 start publish；本地 HTML 变化后旧成功回执不能覆盖新版本。交付调用仍受总预算约束。

```bash
lark-cli apps +create --name "事项名 · 背景包" --app-type html --as user
```

从响应保存 `data.app.app_id`；必须是 `app_` 应用 ID，不能混用鉴权应用的 `cli_` ID。先读取新应用实际可见范围：

```bash
lark-cli apps +access-scope-get --app-id APP_ID --as user
```

预期保持创建者范围，但不能把平台默认值当作已核验事实。若范围无法确认或已扩大，而用户只授权本人可见，先停止发布并报告；不能自行改权限来继续任务。

在 HTML 所在目录执行，相对路径仅指向该文件：

```bash
lark-cli apps +html-publish --app-id APP_ID --path index.html --as user
```

保存 JSON 状态与 `data.url`。若返回 `release_id` 而没有 URL，按本机 `apps +release-get --help` 查询：

```bash
lark-cli apps +release-get --app-id APP_ID --release-id RELEASE_ID --as user
```

轮询到 `finished` 才使用 `online_url`；`failed` 汇报精简错误；等待不应无限持续，默认最多约五分钟，单次等待不超过一分钟。超时保留 app_id/release_id，标注“发布处理中/结果未确认”。不要因无 URL 再创建应用或重复提交发布。

明确确认未应用的失败后先诊断；有可重试原因且预算允许时最多再尝试一次，仍失败保留本地页面并报告 `error.hint`。超时、断网或结果不确定不能标为“未应用”，应记 `unknown` 并优先查询发布记录；`release_id` 存在但未完成记 `submitted`。不自动撤销、删除应用或改共享范围。

## 可见范围与交付

不执行 `+access-scope-set`；“发布页面”和“扩大可见范围”是两项不同授权。聚合页面可能包含只有发起人能访问的材料，原文的逐条权限不会自动保护已经复制到页面中的文本。需要共享时，先让用户确定受众和应当保留的内容，再作为独立明确操作处理。

完成时提供：

1. 阶段一文档链接，或其本地替代产物。
2. 真实发布态 URL（成功响应里的 `data.url` / `online_url`）；否则清楚标注未发布或结果待确认。
3. 实际核验的可见范围和查看时间。只有已确认创建者范围时才说“当前仅你本人可见”。
4. `https://miaoda.feishu.cn/app/APP_ID` 管理入口，明确不能代替发布态链接。
5. 本地 `index.html` 路径和必要的错误/缺口。

已有文档与本地文件都是独立交付物。第二阶段受阻时照常交付，不能把局部失败说成全部失败，也不能把仅生成 HTML 说成发布成功。
